# 복무 · 할일 연동 가이드 (Windows ClassLMS → WorkSupport)

> **대상** — Windows C# 프로그램(ClassLMS)을 만드는 개발자 / AI
> **선행 문서** — `웹소켓_데이터통신규칙.md` 를 **먼저** 읽으십시오.
> 이 문서는 그 문서의 **쓰기(저장) 편**입니다. 접속·티켓·리비전 처리는 반복하지 않습니다.
> 작성일 2026-09-20

---

## 0. 네 줄 요약

1. **읽기**(조회)와 **쓰기**(저장)는 **인증이 다릅니다.** 소켓 티켓으로는 저장할 수 없습니다.
   저장하려면 `WSSESSID` **로그인 세션**이 따로 필요합니다.
2. 저장은 평범한 **HTTP POST + JSON** 입니다. 소켓으로 저장 요청을 보내지 마십시오.
   소켓은 "바뀌었다"를 **받기만** 하는 통로입니다.
3. **로그인했다고 기록할 수 있는 것은 아닙니다.** 할일·복무는 **기록 권한**이 따로 있습니다.
   프로그램을 켤 때 `can_manage` 로 확인하고, 권한이 없으면 **입력 UI 를 아예 보여주지 마십시오.** (§2-4)
4. **복무와 할일은 Google Calendar 로 가지 않습니다.** C# 이 따로 해 줄 일이 없습니다.
   (학사 일정만 갑니다. 그것도 서버가 알아서 합니다)

## 1. 전체 흐름

```
 ┌──────────────┐   ① POST 저장 (HTTP · WSSESSID 쿠키)
 │  C# ClassLMS │ ─────────────────────────────────────► WorkSupport 웹서버
 └──────┬───────┘                                              │
        │                                          ② 같은 트랜잭션에서 outbox 적재
        │                                                      ▼
        │                                              Node 실시간 서버
        │   ④ domain.event 수신 (WebSocket)                     │
        └◄─────────────────────────────────────────────────────┘
                                                        ③ 웹 브라우저에도 동시 전달

        ⑤ 받은 이벤트를 보고 HTTP 로 다시 조회 → 화면 갱신
```

**한 문장으로** — C# 은 웹 화면이 쓰는 것과 **똑같은 HTTP API** 로 저장하고,
그 결과를 **소켓으로 통보받아** 다시 조회합니다. 특별한 경로는 없습니다.

> ⚠ 내가 저장한 변경은 **나에게 되돌아오지 않습니다.** (§4 에코 억제)
> 그러니 저장 성공 응답을 받으면 **기다리지 말고 곧바로 화면에 반영**하십시오.

## 2. ★ 인증 — 두 가지를 따로 들고 있어야 합니다

여기서 가장 많이 막힙니다.

| | 소켓 접속 | HTTP 저장 |
|---|---|---|
| 무엇으로 | 기기 토큰 → **티켓(JWT, 60초)** | 아이디/비밀번호 → **세션 쿠키 `WSSESSID`** |
| 어디에 | `wss://node2.future-class.kr/ws-lms` | `https://future-class.kr/SchoolWork/WorkSupport/...` |
| 유효기간 | 티켓 60초 (접속 시 1회) | **4시간** (마지막 활동 기준) |
| 없으면 | 접속 거부 | `{"ok":false,"msg":"로그인이 필요합니다."}` |

**기기 토큰으로는 저장할 수 없습니다.** 기기 토큰은 "이 PC 가 알림을 받아도 되는가"만 증명합니다.
"누가 이 할일을 만들었는가"는 세션에서만 가져오기 때문입니다.

### 2-1. 로그인

```http
POST https://future-class.kr/SchoolWork/WorkSupport/php/auth/ws_login.php
Content-Type: application/x-www-form-urlencoded

login_id=hong&login_pw=****
```

성공 응답:

```json
{ "ok": true,
  "data": { "user": { "user_id": 12, "name": "홍길동", "role": "teacher",
                      "teacher_id": 7, "position": "교사", ... } },
  "msg": "로그인 성공" }
```

응답 헤더로 `Set-Cookie: WSSESSID=...; Path=/SchoolWork/WorkSupport` 가 내려옵니다.
**이 쿠키를 보관했다가 이후 모든 요청에 실어 보내야 합니다.**

> 쿠키 경로가 `/SchoolWork/WorkSupport` 입니다. `CookieContainer` 를 쓰면 자동으로 맞춰집니다.
> 직접 헤더를 조립하지 마십시오.

### 2-2. 세션 확인 · 연장

```http
GET  .../php/auth/ws_me.php?peek=1     세션만 확인 (활동 시각을 갱신하지 않음)
GET  .../php/auth/ws_me.php?extend=1   사용자가 "연장" 을 눌렀을 때
```

`peek=1` 응답의 `data.expires_in` 이 **남은 초**입니다.

권장 동작:

- 5분마다 `peek=1` 로 확인
- `expires_in < 600` 이면 사용자에게 "세션이 곧 만료됩니다 — 연장하시겠습니까?" 안내
- `ok:false` 또는 HTTP 401 이면 → **저장 버튼을 잠그고** 로그인 창을 띄움

> 만료된 세션으로 저장하면 "로그인이 필요합니다" 만 돌아오고 **데이터는 조용히 사라집니다.**
> 사용자가 공들여 입력한 내용을 잃지 않도록, 재로그인 후 재전송할 수 있게 입력값을 붙들고 계십시오.

### 2-3. 자격증명 보관

- 비밀번호를 **평문으로 파일에 저장하지 마십시오.** Windows DPAPI(`ProtectedData`)를 쓰십시오.
- 저장하지 않는 편이 가장 좋습니다. 프로그램 시작 시 1회 로그인받아 4시간 쓰는 방식을 권합니다.

### 2-4. ★ 기록 권한 — 로그인만으로는 부족합니다

할일과 복무는 **학교 전체가 함께 보는 기록**입니다. 아무나 고치면 곤란하므로,
로그인과 별개로 **기록 권한**이 있는 계정만 추가·수정·삭제할 수 있습니다.

| | 조회(목록 보기) | 기록(추가·수정·삭제) |
|---|---|---|
| 필요한 것 | 없음 | **기록 권한** |
| 누가 | 전원 | 아래 셋 중 하나에 해당하는 계정 |

권한이 인정되는 경우 — **셋 중 하나**면 됩니다.

1. 계정 역할이 **관리자**(`role = 'admin'`)
2. 직위가 **교장 · 교감 · 교무부장 · 행정실장**
3. 관리자가 **사용자 관리 화면에서 "할일 · 복무 기록" 을 개별 허용**한 계정

> 3번은 관리자 메뉴 > 사용자 관리 > 계정 편집 > **접근 가능 메뉴** 의 체크박스입니다.
> 담당 교사 한두 명에게만 열어 주는 용도입니다.

#### 확인 방법 — 두 API 가 같은 답을 줍니다

```http
GET {BASE}/todos.php?action=can_manage
GET {BASE}/duty_status.php?action=can_manage
```

```json
{ "ok": true, "data": { "canManage": true, "grant": "교감" } }
```

| 필드 | 뜻 |
|---|---|
| `canManage` | `true` 면 기록 가능. **이 값만 보면 됩니다** |
| `grant` | 허용 사유 — `"admin"` · 직위명 · `"개별 허용"` · 권한 없으면 `null` |

할일과 복무는 **같은 권한을 씁니다.** 한쪽만 확인해도 되지만,
서버가 나중에 둘을 나눌 수도 있으니 **각 화면에서 해당 API 로 확인**하는 편이 안전합니다.

#### 언제 확인하나

- **로그인 직후 1회** — 결과를 들고 있다가 UI 구성에 씁니다
- 재로그인할 때마다 다시
- 관리자가 방금 권한을 켜 준 경우에도 **재로그인 없이 바로 반영**됩니다
  (서버가 세션이 아니라 DB 를 보고 매번 판정합니다). 사용자가 "권한을 받았다" 고 하면
  `can_manage` 만 다시 호출하면 됩니다.

#### 권한이 없을 때 해야 할 일

- 추가 버튼 · 수정/삭제 버튼 · 완료 체크박스를 **감추거나 비활성화**하십시오
- 목록은 그대로 보여 주십시오. 보는 것은 막을 이유가 없습니다
- 버튼을 남겨 두고 눌렀을 때 오류를 띄우는 방식은 피하십시오. 사용자는 고장이라고 생각합니다

> ⚠ **화면에서 감추는 것은 편의일 뿐, 보안이 아닙니다.**
> 서버가 매 요청마다 다시 검사합니다. 권한 없이 저장을 시도하면
> `"할 일을 기록할 권한이 없습니다. 관리자에게 요청해 주세요."` 가 돌아옵니다.
> 이 응답을 "일시적 오류" 로 보고 재시도하지 마십시오. **재시도해도 계속 실패합니다.**

## 3. 공통 규칙

```
BASE = https://future-class.kr/SchoolWork/WorkSupport/SchoolCalendar/php/api
```

| 항목 | 값 |
|---|---|
| 조회 | `GET  {BASE}/xxx.php?action=list&...` |

```jsonc
// POST 본문 예 — action 이 본문 안에 있습니다
{ "action": "add", "title": "성적 입력 마감", "dueDate": "2026-09-30" }
```

## 4. ★ 에코 억제 — 헤더 두 개

저장 요청에 아래 두 헤더를 **반드시** 붙이십시오.

```http
X-WS-Client-Type: windows
X-WS-Client-Id:   d-3f9a1c2b4e5d6a7b
```

`X-WS-Client-Id` 는 **티켓 발급 응답(`clientId`)에서 받은 값 그대로**입니다. 새로 만들지 마십시오.

이 헤더가 있으면 서버가 "이 변경은 저 PC 가 일으킨 것"을 알고,
**그 PC 에게는 알림을 보내지 않습니다.** 다른 PC 와 웹 브라우저에게만 갑니다.

헤더를 빠뜨리면 — 내가 저장 → 나에게 알림 → 내가 다시 조회 — 라는 불필요한 왕복이 생깁니다.
치명적이지는 않지만 목록이 깜빡이고 트래픽이 두 배가 됩니다.

> 이 값은 **신원 확인에 쓰이지 않습니다.** 위조해도 권한이 생기지 않으니 보안 걱정은 하지 마십시오.
> 신원은 오직 세션에서만 가져옵니다.

## 5. 할일 (Todo)

파일: `todos.php` · 테이블: `school_todos` · 이벤트: `work.calendar.todo.*`

> **기록에는 권한이 필요합니다.** §2-4 를 먼저 읽으십시오.
> `GET {BASE}/todos.php?action=can_manage` → `{"canManage":true,"grant":"개별 허용"}`
> `canManage` 가 `false` 면 추가 버튼·수정/삭제 버튼·완료 체크를 모두 감추십시오.
> **조회는 권한과 무관하게 누구나 됩니다.**

### 5-1. 조회

```http
GET {BASE}/todos.php?action=list
```

```json
{ "ok": true, "data": [
  { "id": 41, "uuid": "9f2c…", "title": "성적 입력 마감",
    "note": "3학년만", "dueDate": "2026-09-30", "deptId": 3,
    "priority": "high", "done": false,
    "gcalTaskId": null, "gcalTaskListId": null, "createdBy": 12 } ] }
```

전체를 한 번에 줍니다. 미완료 → 마감일 순으로 정렬되어 옵니다.

### 5-2. 필드

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `title` | string | ✔ | 비우면 거부 |
| `dueDate` | `"YYYY-MM-DD"` | | 없으면 `null` |
| `deptId` | int | | 담당업무(부서) id. `departments.php?action=list` 참고 |
| `priority` | `"high"\|"medium"\|"low"` | | 다른 값은 `medium` 으로 바뀜 |
| `note` | string | | |
| `done` | bool | | 완료 여부 |
| `gcalTaskId` · `gcalTaskListId` | string | | **§5-5 를 반드시 읽으십시오** |

### 5-3. 추가

```jsonc
POST {BASE}/todos.php
{ "action": "add",
  "title": "성적 입력 마감", "dueDate": "2026-09-30",
  "deptId": 3, "priority": "high", "note": "3학년만" }
```

→ `{ "ok": true, "data": { "id": 41, "uuid": "9f2c…" } }`

`createdBy` 는 **보내지 마십시오.** 서버가 세션에서 넣습니다.

| 응답 `msg` | 뜻 |
|---|---|
| `"로그인이 필요합니다."` | 세션 없음/만료 → 재로그인 |
| `"할 일을 기록할 권한이 없습니다. 관리자에게 요청해 주세요."` | 기록 권한 없음 → **재시도 금지**, 관리자에게 안내 |

추가·수정·삭제 **세 가지 모두** 같은 권한 검사를 거칩니다. 완료 토글도 마찬가지입니다.

### 5-4. 완료 토글

`title` 없이 `done` 만 보내면 **완료 상태만** 바뀝니다. 다른 필드는 건드리지 않습니다.

```jsonc
POST {BASE}/todos.php
{ "action": "update", "id": 41, "done": true }
```

체크박스 동작에는 반드시 이 형태를 쓰십시오.

### 5-5. ★★ 수정할 때의 함정 — 반드시 읽으십시오

`title` 을 함께 보내면 **전체 수정**이 되고, **보내지 않은 필드는 비워집니다.**
부분 수정(PATCH)이 아닙니다.

```jsonc
// ✘ 잘못된 예 — 제목만 고치려다 다른 값이 전부 날아갑니다
{ "action": "update", "id": 41, "title": "성적 입력 마감(연기)" }
//  → done 이 없으므로 pending 으로 되돌아감
//  → dueDate·deptId·note·gcalTaskId 가 전부 NULL 이 됨
```

```jsonc
// ✔ 올바른 예 — list 로 받은 값을 통째로 되돌려 보내고, 바꿀 것만 교체
{ "action": "update", "id": 41,
  "title": "성적 입력 마감(연기)",     // ← 바꾼 값
  "dueDate": "2026-10-07",            // ← 바꾼 값
  "deptId": 3,                        // ↓ 이하는 받은 값 그대로
  "priority": "high",
  "note": "3학년만",
  "done": false,
  "gcalTaskId": null,
  "gcalTaskListId": null }
```

**구현 규칙: 수정 화면은 `list` 로 받은 객체를 통째로 들고 있다가, 사용자가 고친 항목만 덮어쓰고 그 객체 전체를 보낼 것.**

`gcalTaskId` · `gcalTaskListId` 는 C# 이 **의미를 알 필요가 없습니다.**
받은 값을 그대로 되돌려 보내기만 하십시오. 새로 만들거나 임의로 채우면 안 됩니다.

### 5-6. 삭제

```jsonc
POST {BASE}/todos.php
{ "action": "delete", "id": 41 }
```

소프트 삭제(`is_deleted=1`)라 목록에서만 사라집니다.

## 6. 복무사항 (Duty)

파일: `duty_status.php` · 테이블: `school_duty_status` · 이벤트: `work.calendar.duty.*`

교장·교감·교무부장·행정실장의 연가/출장/조퇴를 기록하는 기능입니다.
**개인 근태가 아니라 "관리자 부재 현황" 게시판**에 가깝습니다.

### 6-1. ★ 권한 — 먼저 확인하십시오

```http
GET {BASE}/duty_status.php?action=can_manage
```

```json
{ "ok": true, "data": { "canManage": true, "grant": "교감" } }
```

- `canManage: false` 면 **기록 UI 를 아예 보여주지 마십시오.**
  버튼을 눌러 봐야 `"복무사항을 기록할 권한이 없습니다."` 만 돌아옵니다.
- 조회는 누구나 됩니다. 달력에 표시하는 것은 전원에게 열어 두십시오.
- 기록 권한은 **할일과 동일**합니다 — 관리자 · 교장/교감/교무부장/행정실장 ·
  "할일 · 복무 기록" 개별 허용. 자세한 내용은 §2-4.

### 6-2. 조회 — **달 단위**

```http
GET {BASE}/duty_status.php?action=list&year=2026&month=9
```

```json
{ "ok": true, "data": [
  { "id": 88, "uuid": "1a2b…", "date": "2026-09-24",
    "position": "교감", "dutyType": "출장",
    "timeStart": "13:00", "timeEnd": "17:00", "note": "교육지원청 회의" } ] }
```

`year` · `month` 를 생략하면 **이번 달**이 옵니다. 달을 넘길 때마다 다시 조회하십시오.

### 6-3. 필드 — 값이 정해져 있습니다

| 필드 | 형 | 필수 | 허용값 |
|---|---|---|---|
| `date` | `"YYYY-MM-DD"` | ✔ | |
| `position` | string | ✔ | **`교장` `교감` `교무부장` `행정실장`** — 이 넷뿐 |
| `dutyType` | string | ✔ | **`연가` `출장` `조퇴`** — 이 셋뿐 |
| `timeStart` | `"HH:MM"` | | 종일이면 생략 |
| `timeEnd` | `"HH:MM"` | | |
| `note` | string | | |

> `position` · `dutyType` 은 **한글 문자열을 그대로** 보냅니다. 코드값이 아닙니다.
> 목록에 없는 값을 보내면 거부됩니다. **드롭다운(ComboBox)으로만 입력받으십시오.**
> 직접 타이핑하게 두면 반드시 오타가 납니다.

### 6-4. 추가 · 수정 · 삭제

```jsonc
POST {BASE}/duty_status.php
{ "action": "add", "date": "2026-09-24", "position": "교감",
  "dutyType": "출장", "timeStart": "13:00", "timeEnd": "17:00",
  "note": "교육지원청 회의" }
```

```jsonc
{ "action": "update", "id": 88, "date": "...", "position": "...",
  "dutyType": "...", "timeStart": "...", "timeEnd": "...", "note": "..." }
```

수정도 **전체 교체**입니다. `date` · `position` · `dutyType` 은 매번 보내야 합니다.
(빠뜨리면 검증에 걸려 `"날짜를 입력해주세요."` 등으로 거부됩니다)

```jsonc
{ "action": "delete", "id": 88 }
```

> ⚠ **복무 삭제는 되돌릴 수 없습니다.** 할일과 달리 소프트 삭제가 아니라 **행이 지워집니다.**
> 삭제 전에 반드시 확인 대화상자를 띄우십시오.

## 7. 저장한 뒤에 할 일

```
1. POST 전송
2. 응답의 ok 확인
   · ok:true  → 로컬 목록을 곧바로 갱신하고 화면을 다시 그린다
   · ok:false → msg 를 사용자에게 보여준다. 입력값은 지우지 않는다
3. 끝. 소켓 알림을 기다리지 않는다  ← §4 에코 억제로 나에게는 오지 않는다
```

**저장 응답이 오기 전에 화면을 먼저 바꾸지 마십시오(낙관적 갱신 금지).**
실패했을 때 되돌리기가 어렵고, 사용자는 저장된 줄 알고 프로그램을 닫습니다.

버튼은 전송 동안 비활성화하고, 끝나면 "저장했습니다" 를 잠깐 보여 주십시오.

## 8. 남이 바꿨을 때 — 소켓 이벤트 처리

자세한 절차는 `웹소켓_데이터통신규칙.md` §7 에 있습니다. 여기서는 재조회 대상만 정리합니다.

| 받은 `type` | 다시 읽을 것 |
|---|---|
| `work.calendar.todo.created` / `.updated` / `.deleted` | `todos.php?action=list` (전체) |
| `work.calendar.duty.created` / `.updated` / `.deleted` | `duty_status.php?action=list&year=&month=` — **지금 보고 있는 달만** |

두 이벤트 모두 `scope` 는 **`calendar`** 입니다. 학사 일정과 리비전을 공유합니다.
`module.subscribe` 에 `"calendar"` 하나만 넣으면 일정·할일·복무가 모두 옵니다.

```jsonc
{ "type": "subscribe", "modules": ["calendar", "notice"] }
```

> 이벤트에는 **바뀐 내용이 들어 있지 않습니다.** `resource.id` 만 보고 화면을 고치려 하지 말고,
> 반드시 HTTP 로 다시 읽으십시오. 권한에 따라 보이는 내용이 다르기 때문입니다.

## 9. Google Calendar — **하지 않습니다**

복무와 할일은 Google Calendar 와 연동하지 않습니다. 학사 일정만 연동됩니다.

C# 이 해야 할 일: **없습니다.**

- `channels` 같은 값을 보내려 하지 마십시오. **그런 입력은 받지 않습니다.**
  웹서버가 `todos.php` · `duty_status.php` 에서 내부적으로 "소켓만" 으로 고정합니다.
- Google Calendar API 를 직접 부르지 마십시오.
- 학사 일정을 C# 에서 저장할 때도 마찬가지입니다. `events.php` 로 저장하면
  **서버가 알아서** Google 로 보냅니다. C# 이 관여할 지점이 없습니다.

> 왜 이렇게 나누었나 — 할일·복무는 학교 내부 업무라 외부 캘린더에 실을 이유가 없고,
> 실으면 Google 쪽 변경이 되돌아와 루프가 생길 위험만 커집니다.
