# 학사달력 외 연동 가이드 — 요청사항 · 내 알림 · 법정연수 (Windows ClassLMS)

> **대상** — Windows C# 프로그램(ClassLMS)을 만드는 개발자 / AI
> **선행 문서** — `웹소켓_데이터통신규칙.md`(접속·티켓·리비전), `복무와할일연동_가이드.md`(로그인 세션·에코 억제)
> 이 문서는 **학사 달력 밖의 세 기능**을 다룹니다. 작성일 2026-09-21

---

## 0. 요약

| 기능 | scope | C# 이 들고 있을 것 ("진행 중") | 빠지는 조건 |
|---|---|---|---|
| **요청사항** | `request` | 나에게 온 요청 · 내가 올린 요청 중 **요청/처리 중** | 완료 · 종료 · 삭제 · (지정 대상 글에서) 내가 처리완료 표시 |
| **내 알림** | `notice` | **읽지 않은** 알림 | 읽음 · 삭제 |
| **법정연수** | `training` | 내가 낼 이수증(**미제출 · 보완요청**) + 내가 확인할 제출(**확인대기**) | 제출함(확인대기) · 이수확인 · 과정 삭제 |

규칙 다섯 줄.

1. 이벤트에는 **내용이 없습니다.** `hint` 로 "나와 관련 있는가 / 아직 진행 중인가" 만 판단하고 **목록은 HTTP 로 다시 읽습니다.**
2. 다시 읽을 때는 **진행 중인 것만 주는 전용 API**(`action=active`)를 씁니다. 완료된 것은 서버가 걸러 줍니다.
3. **알림(토스트)은 `notice` 이벤트에서만 띄웁니다.** 요청사항·연수 이벤트는 목록 동기화 전용입니다.
   (같은 사건에 두 이벤트가 함께 오므로, 둘 다에서 띄우면 알림이 두 번 뜹니다)
4. 이 세 기능의 API 는 **폼 전송(form-urlencoded)** 이고 응답의 메시지 키가 **`message`** 입니다.
   학사 달력 API(JSON 전송 · `msg`)와 **다릅니다.** JSON 으로 보내면 오류 없이 **목록 조회로 처리되어**
   저장이 조용히 무시됩니다. §3
5. 요청사항 **상세 조회(`action=detail`)는 "읽음 처리"를 겸합니다.** 동기화 목적으로 부르지 마십시오. §4-4

## 1. 구독

```json
{ "type": "subscribe", "modules": ["calendar", "notice", "request", "training"] }
```

| 이벤트가 가는 곳 | 구독 필요 | 예 |
|---|---|---|
| 내 개인 Room (`user:<나>`) | **자동** (접속만 하면 됨) | 알림 전부, 지정 대상 요청사항, 내 이수증 |
| 기능 Room (`module:request` · `module:training`) | `subscribe` 필요 | **전체 공개** 요청사항, **전체 대상** 연수 과정 |

> `request` · `training` 을 구독하지 않으면 **전체 공개 글**의 변경을 놓칩니다.
> 지정 대상 글은 구독과 무관하게 대상자 본인에게 옵니다.

**받는 사람은 서버가 정합니다.** 지정 대상 요청사항은 대상자와 작성자에게만, 이수증 제출은
제출자와 과정 등록자에게만 갑니다. 권한 없는 사람에게는 "바뀌었다" 는 사실도 가지 않습니다.

> ⚠ 한계 — 부장·관리자는 웹에서 모든 요청사항을 볼 수 있지만, **자신이 대상·작성자가 아닌
> 지정 대상 글**의 변경은 실시간으로 받지 않습니다. 다음 재동기화(재접속 · 5분 주기) 때 반영됩니다.

## 2. 공통 메시지 모양

`웹소켓_데이터통신규칙.md` §5 의 `domain.event` 와 같습니다. 이 문서의 이벤트는 여기에 `hint` 가 붙습니다.

```json
{ "type": "domain.event", "data": {
    "eventId": "…", "type": "work.request.status.changed",
    "scope": "request", "revision": 57, "op": "updated",
    "resource": { "type": "schoolwork_requests", "id": "31" },
    "actor": { "userId": 12, "name": "정선구" },
    "origin": { "clientType": "web" },
    "fields": ["status"],
    "hint": { "statusFrom": "doing", "status": "done", "active": false,
              "targetType": "selected", "createdBy": 12 } } }
```

- `resource.id` 는 **문자열**로 옵니다. 정수로 바꿔 쓰십시오.
- 한 사건이 여러 명에게 가면 서버가 8명씩 나눠 보냅니다. 그래서 **리비전 번호가 건너뛰어** 보일 수 있습니다.
  정상입니다. 수신 규칙은 "현재값 이하이면 버림" 뿐이며 연속을 요구하지 않습니다.
- 모르는 `type` · 모르는 `hint` 키는 **조용히 무시**하십시오.

## 3. HTTP API 공통 — 학사 달력과 다른 점

```
BASE = https://future-class.kr/SchoolWork/WorkSupport/php/features
```

| 항목 | 학사 달력 (`SchoolCalendar/php/api/*`) | **이 문서 (`php/features/*`)** |
|---|---|---|
| POST 본문 | JSON | **`application/x-www-form-urlencoded`** (첨부 시 multipart) |
| `action` 위치 | JSON 본문 안 | **폼 필드** (`action=read&id=5`) · GET 은 쿼리스트링 |
| 응답 | `{ok, data, msg}` | `{ok, data, `**`message`**`}` |
| 인증 | 조회는 무인증 | **조회도 로그인 필수** (`WSSESSID`) |
| 권한 없음 | HTTP 200 + `ok:false` | HTTP **401 / 403 / 404** + `ok:false` |

```csharp
// 폼 전송 — JSON 이 아닙니다
var form = new FormUrlEncodedContent(new Dictionary<string,string> {
    ["action"] = "read", ["id"] = "57" });
var res = await _http.PostAsync($"{Base}/notifications.php", form);   // + X-WS-Client-* 헤더
```

응답 판정: HTTP 401 → 재로그인 · 그 외에는 `ok` 가 `false` 면 `message` 를 사용자에게 보여 줍니다.

`link` 필드는 **상대 경로**(`/SchoolWork/WorkSupport/features/requests.html?id=31`)입니다.
앞에 `https://future-class.kr` 을 붙여 기본 브라우저로 열면 됩니다.

## 4. 요청사항 (`scope = request`)

### 4-1. 진행 중 목록 — 초기 적재 · 재조회

```http
GET {BASE}/requests.php?action=active
```

```json
{ "ok": true, "data": { "year": 2026, "me": 12, "items": [
  { "id": 31, "title": "교실 안전점검 결과 제출", "category": "자료요청",
    "priority": "high", "priority_label": "긴급",
    "status": "doing", "status_label": "처리 중",
    "due_date": "2026-09-25", "is_overdue": false,
    "created_by": 7, "created_name": "김교감", "created_at": "2026-09-18 09:12:00",
    "target_type": "selected",
    "role": "to_me",
    "my_read": false, "my_done": false,
    "comment_count": 2, "target_count": 14, "done_count": 9,
    "link": "/SchoolWork/WorkSupport/features/requests.html?id=31" } ] } }
```

| 필드 | 뜻 |
|---|---|
| `role` | `"to_me"` 나에게 온 글 · `"mine"` 내가 올린 글 |
| `my_read` | 내가 읽었는가 (내 글이면 항상 true) |
| `my_done` | 지정 대상 글에서 내가 "처리완료" 표시했는가 (표시했으면 애초에 목록에 안 옵니다) |
| `done_count` / `target_count` | 내 글의 진행 현황 (지정 대상 글만 의미 있음) |
| `is_overdue` | 기한이 지났는데 아직 진행 중 |

**서버가 이미 걸러 주는 것**: 완료(`done`) · 종료(`closed`) · 삭제 · 다른 학년도 · 볼 권한 없는 글 ·
내가 처리완료 표시한 지정 대상 글. **C# 은 받은 목록을 그대로 쓰면 됩니다.**

### 4-2. 이벤트

| type | 언제 | 받는 사람 |
|---|---|---|
| `work.request.created` | 새 글 | 전체 공개: 구독자 전원 · 지정: 대상자+작성자 |
| `work.request.updated` | 글 수정 · 첨부 삭제(`fields:["files"]`) | 〃 (+ **대상에서 빠진 사람**) |
| `work.request.status.changed` | 상태 변경 (`fields:["status"]`) | 〃 |
| `work.request.deleted` | 삭제 | 〃 |
| `work.request.comment.created` / `.updated` / `.deleted` | 댓글 | 〃 |
| `work.request.target.done` | 대상자가 처리완료 표시/해제 | **작성자 + 본인만** |

### 4-3. hint

| 키 | 값 | 뜻 |
|---|---|---|
| `active` | bool | **진행 중이면 true.** false 면 목록에서 빼십시오 |
| `status` | `open` `doing` `done` `closed` | 변경 후 상태 (요청 · 처리 중 · 완료 · 종료) |
| `statusFrom` | 〃 | 상태 변경 이벤트에서 이전 상태 |
| `targetType` | `all` `selected` | 전체 공개 / 지정 대상 |
| `createdBy` | int | 작성자 user_id — 내 글인지 판단 |
| `commentId` · `byUser` | int | 댓글 이벤트 — 누가 달았나 |
| `userId` · `done` | int · bool | 처리완료 이벤트 — 누가 표시/해제했나 |

### 4-4. 처리 규칙

```
받음 → (§7 공통 절차: 중복·메아리·리비전)
  ├─ hint.active == false        → 로컬 목록에서 resource.id 제거
  ├─ type == target.done         → hint.userId == 나  ? 내 목록에서 제거(done) / 다시 추가(해제)
  │                                 hint.createdBy == 나 ? 진행 현황(done_count)만 갱신
  └─ 그 외                       → requests.php?action=active 재조회 (묶어서 1회)
```

- 재조회는 **400ms 정도 모았다가 한 번** 하십시오. 전체 공지 한 건에도 이벤트가 여러 개 옵니다.
- **`action=detail` 을 동기화에 쓰지 마십시오.** 상세 조회는 그 자체로
  ① 요청사항을 "읽음" 처리하고 ② 관련 알림까지 읽음 처리합니다.
  사용자가 **실제로 열어 볼 때만** 부르거나, 웹 페이지(`link`)를 열어 주십시오.

### 4-5. C# 에서 할 수 있는 동작

| 동작 | 요청 | 누가 |
|---|---|---|
| 내 몫 처리완료 / 해제 | `POST requests.php` `action=target_done&id=31&done=1` (`done=0` 해제) | 지정 대상자 |
| 댓글 달기 | `POST requests.php` `action=comment_save&request_id=31&body=…` | 볼 수 있는 사람 |
| 상태 변경 | `POST requests.php` `action=status&id=31&status=done` | 작성자 · 부장 이상 |
| 읽고 상세 보기 | `GET requests.php?action=detail&id=31` (읽음 처리됨) | 볼 수 있는 사람 |

> 글 등록·수정(대상 선택 · 첨부)은 화면이 복잡하므로 **웹 페이지를 여는 방식**을 권합니다.
> `status` 값은 `open` `doing` `done` `closed` 넷뿐입니다.
> 전체 공개 글에는 개인별 처리완료가 없습니다(`target_done` 이 아무 일도 하지 않음). 글이 완료될 때까지 목록에 남습니다.

## 5. 내 알림 (`scope = notice`)

### 5-1. 진행 중 목록 = 읽지 않은 알림

```http
GET {BASE}/notifications.php?action=list&only_unread=1&limit=100
GET {BASE}/notifications.php?action=count          → { "unread": 3 }
```

```json
{ "ok": true, "data": { "unread": 3, "items": [
  { "id": 905, "type": "request", "title": "교실 안전점검 결과 제출",
    "body": "9/25까지 제출 부탁드립니다…", "link": "/SchoolWork/…/requests.html?id=31",
    "ref_type": "request", "ref_id": 31,
    "is_read": 0, "created_name": "김교감", "created_at": "2026-09-21 09:12:00" } ] } }
```

`type` — `request`(요청사항 안내) · `comment`(내 글에 댓글) · `training`(연수 안내·제출·보완요청) · `meeting` · `system`

### 5-2. 이벤트

| type | 언제 | hint |
|---|---|---|
| `work.notice.created` | 나에게 새 알림 | `kind`(=알림 type) · `refType` · `refId` |
| `work.notice.read` | 읽음 (한 건 · 전체 · 요청사항 상세를 열어서) | `id` 또는 `all:true` 또는 `refType`+`refId` · **`unread`** |
| `work.notice.deleted` | 삭제 | `id` · **`unread`** |

모두 **내 개인 Room** 으로만 옵니다. 다른 사람의 알림은 오지 않습니다.

### 5-3. 처리 규칙

```
work.notice.created  → list&only_unread=1 재조회 → 새로 생긴 항목의 title 로 토스트  ★ 토스트는 여기서만
work.notice.read     → hint.unread 로 배지 갱신 (재조회 불필요)
                       hint.id 가 있으면 그 항목 제거 · hint.all 이면 전부 제거
                       hint.refType/refId 면 그 ref 의 알림들 제거
work.notice.deleted  → hint.unread 로 배지 · hint.id 항목 제거
```

> 웹에서 읽으면 C# 배지가 줄고, C# 에서 읽으면 웹 종 아이콘 숫자가 줄어듭니다. 같은 사람의 두 화면이 맞춰집니다.

### 5-4. C# 에서 할 수 있는 동작

| 동작 | 요청 |
|---|---|
| 한 건 읽음 | `POST notifications.php` `action=read&id=905` |
| 전체 읽음 | `POST notifications.php` `action=read_all` |
| 삭제 | `POST notifications.php` `action=delete&id=905` |

응답의 `data.unread` 로 배지를 바로 고치십시오. 이미 읽은 것을 다시 읽음 처리하면 이벤트는 나가지 않습니다.

## 6. 법정연수 이수증 (`scope = training`)

### 6-1. 진행 중 목록

```http
GET {BASE}/training.php?action=active
```

```json
{ "ok": true, "data": { "year": 2026, "me": 12,
  "todo": [
    { "id": 6, "title": "교직원 성희롱 예방교육", "category": "법정연수",
      "required_hours": 1, "due_date": "2026-10-31", "is_required": true, "is_overdue": false,
      "status": null, "status_label": "미제출", "record_id": null, "review_note": null,
      "created_by": 2, "created_name": "김교감",
      "link": "/SchoolWork/WorkSupport/features/training.html?course=6" },
    { "id": 7, "title": "아동학대 예방교육", "status": "rejected", "status_label": "보완요청",
      "record_id": 41, "review_note": "이수증 이미지가 흐립니다", "…": "…" } ],
  "review": [
    { "id": 9, "title": "심폐소생술", "due_date": "2026-11-15",
      "pending_count": 3, "last_submitted_at": "2026-09-21 10:02:11",
      "link": "/SchoolWork/WorkSupport/features/training.html?course=9" } ] } }
```

| 목록 | 무엇 | 빠지는 조건 |
|---|---|---|
| `todo` | 내가 이수증을 내야 하는 과정 (`status` 가 `null`=미제출 또는 `rejected`=보완요청) | 제출(확인대기) · 이수확인 · 과정 삭제 |
| `review` | **내가 등록한** 과정 중 확인을 기다리는 제출이 있는 것 | 대기 건이 0 |

### 6-2. 이벤트

| type | 언제 | 받는 사람 |
|---|---|---|
| `work.training.course.created` / `.updated` / `.deleted` | 과정 등록·수정·삭제 | 전체 대상: 구독자 전원 · 지정: 대상자+등록자(+대상에서 빠진 사람) |
| `work.training.record.submitted` | 이수증 제출·재제출 | **제출자 · 과정 등록자** |
| `work.training.record.reviewed` | 이수확인 / 보완요청 | 제출자 · 과정 등록자 · 처리자 |
| `work.training.record.deleted` | 제출 삭제 | 제출자 · 과정 등록자 · 처리자 |

### 6-3. hint

| 키 | 이벤트 | 뜻 |
|---|---|---|
| `courseId` | 전부 | 과정 id |
| `active` | course.* | 과정이 살아 있으면 true (삭제면 false) |
| `targetType` · `createdBy` | course.* | 전체/지정 · 등록자 |
| `userId` | record.* | **제출한 사람** |
| `status` | record.* | `submitted` 확인대기 · `approved` 이수확인 · `rejected` 보완요청 · `null` 기록 없음(삭제) |
| `todo` | record.* | 제출자 입장에서 **아직 할 일인가** (`null` 또는 `rejected` 이면 true) |
| `courseCreatedBy` | record.* | 과정 등록자 — 내가 확인할 사람인지 판단 |

### 6-4. 처리 규칙

```
course.* 또는 record.*  → training.php?action=active 재조회 (묶어서 1회)

다만 재조회 없이 바로 알 수 있는 것:
  record.* 이고 hint.userId == 나        → hint.todo 가 true 면 todo 에 있어야 함 / false 면 빠져야 함
  record.* 이고 hint.courseCreatedBy == 나 → review 의 pending_count 가 바뀜
  course.deleted                         → todo · review 에서 hint.courseId 제거
```

"보완요청을 받았다" 같은 사용자 알림은 **`work.notice.created`(kind=`training`)** 로 따로 옵니다. 토스트는 그쪽에서 띄우십시오.

### 6-5. C# 에서 할 수 있는 동작

| 동작 | 요청 | 누가 |
|---|---|---|
| 이수확인 / 보완요청 | `POST training.php` `action=review&id=<record_id>&status=approved` (보완: `status=rejected&note=…`) | 과정 등록자 · 부장 이상 |
| 이수증 제출 | `POST training.php` **multipart** `action=submit&course_id=6&completed_at=2026-09-20&hours=1` + 파일 `cert_file` | 대상자 |

> 제출은 파일 첨부가 필수라(첫 제출 시) **웹 페이지를 여는 방식**을 권합니다.
> 확인할 제출 목록(`record_id`)은 `GET training.php?action=detail&id=<과정id>` 로 얻습니다.

## 7. 공통 수신 절차 — 세 기능 모두

`웹소켓_데이터통신규칙.md` §7 과 같습니다.

```
domain.event 수신
 ├─ eventId 중복 → 버림
 ├─ origin.clientId == 내 clientId → 버림 (내 메아리 · 서버가 이미 걸러 주지만 한 번 더)
 ├─ revision <= _rev[scope] → 버림
 ├─ _rev[scope] = revision
 └─ scope 별 처리 (§4-4 · §5-3 · §6-4)
```

재접속 · 절전 복귀 시에는 티켓의 `revisions` 와 비교해서 **값이 커진 scope 의 `active` 목록을 다시 읽습니다.**
알림은 `notifications.php?action=list&only_unread=1` 을 다시 읽습니다.

## 8. C# 골격

```csharp
public sealed class ActiveSync
{
    private readonly WorkSupportApi _api;           // 복무와할일연동_가이드.md §10 의 클래스 (쿠키 · 헤더 포함)
    private readonly int _me;
    private readonly Debouncer _reqReload, _trReload, _ntReload;   // 400ms 묶음

    public List<RequestItem>  Requests { get; private set; } = new();
    public List<TrainingTodo> Todo     { get; private set; } = new();
    public List<TrainingRev>  Review   { get; private set; } = new();
    public List<Notice>       Unread   { get; private set; } = new();
    public int UnreadCount { get; private set; }

    public ActiveSync(WorkSupportApi api, int me)
    {
        _api = api; _me = me;
        _reqReload = new(TimeSpan.FromMilliseconds(400), ReloadRequestsAsync);
        _trReload  = new(TimeSpan.FromMilliseconds(400), ReloadTrainingAsync);
        _ntReload  = new(TimeSpan.FromMilliseconds(400), ReloadNoticesAsync);
    }

    /// 로그인 · 재접속 직후
    public Task LoadAllAsync() => Task.WhenAll(ReloadRequestsAsync(), ReloadTrainingAsync(), ReloadNoticesAsync());

    public void OnEvent(DomainEvent e)          // §7 공통 절차를 통과한 이벤트만 들어온다
    {
        var h = e.Hint;
        switch (e.Scope)
        {
            case "request":
                if (h?.Active == false) { Requests.RemoveAll(r => r.Id == e.ResourceIdInt); Changed(); }
                else if (e.Type == "work.request.target.done" && h?.UserId == _me)
                {
                    if (h.Done == true) { Requests.RemoveAll(r => r.Id == e.ResourceIdInt); Changed(); }
                    else _reqReload.Trigger();
                }
                else _reqReload.Trigger();
                break;

            case "training":
                if (e.Type == "work.training.course.deleted")
                {
                    Todo.RemoveAll(t => t.Id == h!.CourseId);
                    Review.RemoveAll(r => r.Id == h!.CourseId);
                    Changed();
                }
                else _trReload.Trigger();
                break;

            case "notice":
                if (e.Type == "work.notice.created") { _ntReload.Trigger(); break; }   // 토스트는 재조회 후
                if (h?.Unread is int n) UnreadCount = n;
                if (h?.All == true)          Unread.Clear();
                else if (h?.Id is int id)    Unread.RemoveAll(x => x.Id == id);
                else if (h?.RefType != null) Unread.RemoveAll(x => x.RefType == h.RefType && x.RefId == h.RefId);
                Changed();
                break;
        }
    }

    private async Task ReloadNoticesAsync()
    {
        var before = Unread.Select(x => x.Id).ToHashSet();
        (Unread, UnreadCount) = await _api.GetUnreadNoticesAsync();      // list&only_unread=1
        foreach (var n in Unread.Where(x => !before.Contains(x.Id)))
            ShowToast(n.Title, n.Link);                                   // ★ 토스트는 여기서만
        Changed();
    }

    private async Task ReloadRequestsAsync() { Requests = await _api.GetActiveRequestsAsync(); Changed(); }
    private async Task ReloadTrainingAsync() { (Todo, Review) = await _api.GetActiveTrainingAsync(); Changed(); }

    private void Changed() { /* UI 스레드로 목록 갱신 */ }
    private void ShowToast(string title, string link) { /* 클릭 시 https://future-class.kr + link 열기 */ }
}
```

> 처음 로그인했을 때 이미 쌓여 있던 미읽음 알림까지 토스트로 띄우지 마십시오.
> `LoadAllAsync()` 에서는 `before` 를 채운 뒤 비교하거나, 첫 적재는 토스트 없이 끝내십시오.

## 9. 체크리스트

- [ ] `subscribe` 에 `"notice"`, `"request"`, `"training"` 을 넣었는가
- [ ] 세 API 를 **폼 전송**으로 부르고, 응답에서 **`message`** 를 읽는가
- [ ] HTTP 401 이면 재로그인으로 가는가
- [ ] 초기 적재·재조회에 **`action=active`** (요청사항·연수)와 **`only_unread=1`** (알림)을 쓰는가
- [ ] `hint.active == false` 면 재조회 없이 목록에서 빼는가
- [ ] 여러 이벤트를 **묶어서 한 번만** 재조회하는가 (400ms)
- [ ] **토스트는 `work.notice.created` 에서만** 띄우는가 (두 번 뜨지 않는가)
- [ ] 첫 적재 때 기존 미읽음으로 토스트를 쏟아내지 않는가
- [ ] `requests.php?action=detail` 을 **동기화 목적으로 부르지 않는가** (읽음 처리됨)
- [ ] `notice.read`/`deleted` 의 `hint.unread` 로 배지를 바로 고치는가
- [ ] 저장 요청에 `X-WS-Client-Type: windows` · `X-WS-Client-Id` 를 붙이는가
- [ ] `link` 앞에 `https://future-class.kr` 을 붙여 여는가

## 10. 자주 나는 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| 저장했는데 **아무 변화 없이 목록이 돌아옴** (`ok:true`) | JSON 본문으로 보냄 → 서버가 `action` 을 못 읽고 기본값 `list` 로 처리 | **폼 전송** (`FormUrlEncodedContent`). 가장 흔하고 눈치채기 어려운 실수입니다 |
| 오류 문구가 비어 있음 | `msg` 를 읽음 | 이 API 는 **`message`** |
| HTTP 401 | 세션 만료 | 재로그인 |
| HTTP 403 `"권한이 없습니다."` | 작성자·등록자·부장 이상만 가능한 동작 | 버튼 감추기 (`role`, `created_by` 로 판단) |
| 전체 공개 요청이 실시간으로 안 옴 | `request` 미구독 | §1 |
| 알림이 두 번 뜸 | request/training 이벤트에서도 토스트 | 토스트는 notice 에서만 |
| C# 을 켜 두기만 했는데 요청사항이 "읽음" 이 됨 | 동기화에 `action=detail` 사용 | `action=active` 로 바꾸십시오 |
| 처리완료 표시했는데 목록에 남음 | 전체 공개 글 | 전체 공개 글은 개인별 처리완료가 없습니다 (글 완료 시 빠짐) |
