# 라이센스 인증 상태 보고 API — 서버 팀 요청안

> 이 문서는 다른 문서들(`웹소켓_데이터통신규칙.md` 등)과 반대 방향입니다 — 서버 팀이
> 클라이언트(C#, `LmsAgent`) 쪽에 내려준 규약이 아니라, **클라이언트 쪽에서 서버 팀에
> 새로 만들어 주십사 요청하는 API 계약안**입니다. 아직 서버에 구현되어 있지 않으며,
> 이 문서의 형식은 어디까지나 제안입니다 — 서버 팀 사정에 맞게 경로·필드명 등을
> 자유롭게 조정해 주셔도 됩니다. 확정되면 이 문서를 그대로 갱신하고 C# 쪽 구현을
> 이어서 진행하겠습니다.

## 1. 배경 및 목적

환경설정 &gt; 라이센스에서 각 PC는 자체적으로 인증키를 입력하고, 로그인 직후
(`LicenseGuardService.CheckAsync`) 그 값을 학교 정보의 `auth_key`(현재
`php/features/school.php?action=get`가 내려주는 값)와 **클라이언트 쪽에서만** 대조합니다.
불일치하면 안내 후 3분 뒤 프로그램이 스스로 종료합니다.

이 구조에서 "정답" 자체는 이미 서버(학교 정보의 `auth_key`)가 쥐고 있어서, 마스터가
그 값을 웹에서 바꾸면 모든 PC의 검증 기준이 즉시 바뀝니다. 다만 **지금은 그 반대 방향
정보가 전혀 없습니다** — 어느 PC가 지금 어떤 키를 입력해 두었는지, 검증에 통과했는지
실패했는지, 실패했다면 언제부터인지를 서버(관리자 화면)에서 전혀 확인할 수 없습니다.
불일치가 나면 사용자가 프로그램이 꺼진 이유를 직접 물어봐야만 알 수 있는 상태입니다.

**요청 사항**: 각 PC가 라이센스 검사를 할 때마다 그 결과를 서버로 짧게 보고하는 API를
하나 추가해 주시고, 그 보고를 학교별로 모아 보여줄 수 있는 목록을 관리자 화면(마스터)
쪽에 만들어 주시면 좋겠습니다. 후자(관리자 화면)는 전적으로 서버 팀 재량이며, 이 문서는
그 화면이 참고할 **데이터를 쌓는 API 계약**만 다룹니다.

## 2. 제안하는 엔드포인트

기존 "부가 기능" 계열(`php/features/*`, 폼 인코딩, 로그인 필요, 오류 메시지는
`message` 키)과 동일한 규칙을 그대로 따르는 새 엔드포인트를 제안합니다.

```
POST {BASE}/php/features/license_status.php
Content-Type: application/x-www-form-urlencoded
```

(기존 `school.php?action=get`과 같은 파일에 `action=report_license`로 추가하는 형태도
무방합니다 — 서버 팀이 관리하시기 편한 쪽으로 정해 주세요.)

### 요청 필드

| 필드 | 값 | 비고 |
|---|---|---|
| `status` | `"valid"` \| `"invalid"` \| `"not_configured"` | `LicenseGuardService.LicenseStatus`와 1:1 대응 |
| `entered_key` | 환경설정에 입력된 인증키 원문 | `status=not_configured`(서버에 auth_key 자체가 없음)일 때는 빈 문자열 가능 |
| `device_name` | PC 이름(`Environment.MachineName`) | 여러 PC를 구분하는 용도. 사람이 읽을 수 있는 이름이라 PC를 바꿔 달면 값도 바뀔 수 있음(고유 식별자는 아님) |
| `app_version` | 실행 중인 프로그램 파일 버전(예: `1.3.0.0`) | 오래된 버전이 계속 검사 실패 중인지 등을 구분하는 데 참고 |
| `checked_at` | 검사 시각(로컬 시각, ISO 8601, 예: `2026-09-28T09:15:00+09:00`) | 서버 수신 시각과 별개로 클라이언트 시계 기준 시각도 함께 참고할 수 있도록 |

인증은 기존 "부가 기능" 계열과 동일하게 **로그인 세션 쿠키(`WSSESSID`)** 로 충분합니다
— 이 보고 자체가 로그인 직후에만 일어나므로, 별도의 인증 수단은 필요 없다고 봅니다.
어느 학교·어느 계정의 PC인지는 세션에서 이미 알 수 있으므로 요청 본문에 학교/사용자
식별자를 따로 싣지 않았습니다.

### 응답

기존 부가 기능 계열과 동일하게, 다른 API들과 같은 공통 봉투 형식이면 충분합니다.

```json
{ "ok": true }
```

실패 시:

```json
{ "ok": false, "message": "오류 설명" }
```

### 호출 시점 (클라이언트 쪽 구현 계획)

`LicenseGuardService.CheckAsync()`가 상태를 판정한 직후(`SetStatus(...)` 호출 지점)
그대로 이 API를 한 번 호출합니다 — 즉 로그인 직후 최초 1회, 그리고 인증키가 바뀌어
환경설정에서 다시 검사할 때마다 보고합니다. 별도의 주기적 재전송(예: 몇 분마다 재확인)은
지금 계획에는 없습니다 — 필요하시면 알려주시면 그에 맞게 클라이언트도 조정하겠습니다.
보고 자체가 실패해도(네트워크 오류 등) 로컬의 라이센스 판정·3분 자동 종료 로직에는
영향을 주지 않을 예정입니다(부가 기능이 본 기능을 막으면 안 되므로).

## 3. 관리자 화면에 필요할 것으로 예상되는 목록 (참고용 제안)

아래는 화면 설계를 대신하려는 것이 아니라, 위 API가 쌓아야 할 데이터가 무엇에 쓰이는지
가늠하실 수 있도록 참고로 적어 둡니다.

- PC별 최신 상태 한 줄: PC 이름, 로그인 계정(세션에서 이미 알 수 있음), 상태(정상/불일치/
  미설정), 입력된 키, 마지막 보고 시각, 프로그램 버전.
- 상태가 "불일치"인 행을 눈에 띄게 표시(마스터가 "이 PC가 왜 꺼지는지" 바로 알 수 있도록).
- (선택) 이력을 남길지, 아니면 PC(또는 계정)별 "최신 1건"만 덮어쓸지는 서버 팀 판단에
  맡깁니다 — 클라이언트 입장에서는 매번 "지금 상태"만 보고하면 되므로 어느 쪽이든
  API 계약 자체는 바뀔 필요가 없습니다.

## 4. 보안 고려 사항

- 인증키(`entered_key`)는 비밀번호가 아니라 **학교 단위로 공유되는 조직 라이센스 값**
  이므로(현재도 서버의 `auth_key`와 평문으로 대조합니다), 평문으로 보고해도 기존 보안
  수준과 같습니다. 다만 저장 시 관리자 화면 접근 권한이 있는 사람만 볼 수 있도록 해 주세요.
- 이 보고는 이미 로그인된 세션에서만 일어나므로, 로그인 여부와 무관하게 익명으로
  호출 가능한 엔드포인트가 되지 않도록(다른 부가 기능 API와 동일하게 로그인 필수로)
  부탁드립니다.

## 5. 이 문서에 대한 C# 쪽 구현 상태

**아직 구현 전입니다.** 위 계약(경로·필드명·응답 형식)이 서버 팀 쪽에서 확정되면,
`WorkSupportApiClient`에 `ReportLicenseStatusAsync(...)` 메서드를 추가하고
`LicenseGuardService.CheckAsync()`의 `SetStatus(...)` 호출 지점에서 함께 호출하도록
연결하겠습니다. 확정된 실제 경로/필드가 이 문서와 다르면, 이 문서를 그 내용대로 갱신한
뒤 구현하겠습니다.
